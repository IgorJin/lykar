# SERVICE-V1-07 — Доставка писем входа и приглашений

Status: IN_PROGRESS
Priority: P0
Depends on: SERVICE-V1-06, SERVICE-V1-12
Parallel wave: W7
Can run in parallel with: None

Stage: E3 — S6: регистрация и самостоятельное подключение
Planning date: 2026-10-02

## Goal

Доставлять пользователю рабочие ссылки через выбранного email provider.

## Problem solved

По умолчанию sender печатает секретную ссылку в API log, а пользователю нечего открыть в почте.

## Enables

- Регистрацию и приглашения вне локального стенда.
- Последующую очередь повторной отправки.

## Scope

- Подключить выбранного в 02 provider через MagicLinkSender/InvitationSender; секреты остаются на сервере.
- Добавить шаблоны, срок действия, возврат в нужный контекст и безопасные статусы отправки.
- Production startup проверяет обязательную конфигурацию; console/file senders остаются только test/dev.
- Не логировать URL/token/authorization/cookie; хранить безопасный delivery ID для поддержки.
- Проверить успешную и неуспешную отправку на контролируемые тестовые ящики; retry contract подготовить для 14.

## Parallel execution

Последовательно после auth; общий sender contract фиксируется до очереди 14.

Hard prerequisites: SERVICE-V1-06, SERVICE-V1-12. Все транзитивные prerequisites обязательны. Изменение общей схемы/контракта/lockfile или использование одного mutable стенда требует последовательного checkpoint.

## Acceptance criteria

- [ ] Письмо входа и приглашение реально приходят на тестовый адрес и открывают HTTPS staging.
- [x] Ошибка provider даёт определённый результат без утечки ссылки в логах и без ложного «доставлено».
- [x] Истёкшая/повторная ссылка и resend понятны пользователю; tokens не попадают в reports.
- [x] Production нельзя запустить с default console sender.

## Дополнение владельца — 2026-10-05

Включить в этот этап ограничение запросов писем и переключение настроенных email-провайдеров по квотам. В 06 это не реализуется.

- Не более 3 запросов на нормализованный email за согласованное окно; предложено 1 час и пауза 60 секунд. Окно и пауза пока PROPOSED. Уточнить общий/раздельный бюджет login и invitations, дополнить IP/actor лимитами.
- Общие атомарные счётчики в PostgreSQL для нескольких API-процессов; перезапуск не сбрасывает лимит. 429 + Retry-After; одинаковое поведение известных/новых адресов, без raw email/IP/token в логах.
- Упорядоченный список подключённых провайдеров (предложены Resend → MailerSend), квоты суток и фактического billing period, резерв до бесплатного предела. Выбор/условия/доступность провайдеров и даты сброса проверить при подключении.
- Переключать только при исчерпании локальной квоты либо доказанном непринятии письма. Timeout/неопределённое принятие не вызывает повтор через другой сервис; нужна защита от дублей и безопасная диагностика.
- Учитывать отправки login и invitation вместе, внешние отправки/синхронизацию usage и ошибки provider. Не переходить автоматически на платные превышения. При исчерпании всех квот — понятный временный отказ, без ложного «доставлено».
- Проверить конкурентные запросы, смену IP/email, границы окон, сброс квот, restart, общие quota reservations, недоставку и отсутствие дублей. Реальные письма — только на контролируемые ящики этапа 07.

Пользователь перенёс эту реализацию в следующий план и поручил сначала закончить 06. Незавершённый локальный прототип снят; он не считается выполненной частью этапа.


## Реализация без ключа — 2026-10-05

Владелец поручил перейти к 07 без реального API-ключа. Локальная реализация
выполнена отдельно от внешнего gate 12; статус IN_PROGRESS сохраняет открытую
проверку реального ящика и HTTPS staging. API credentials не запрашивались,
внешние письма не отправлялись, аккаунты/платные сервисы не создавались.

- Resend и MailerSend adapters, русские HTML/text шаблоны, 10s timeout,
  sanitised ошибки, безопасный delivery ID. Disabled/file режимы для работы без ключа.
- Настраиваемый стартовый профиль: 3/email/час, 60s пауза, 30/IP или actor/час.
  Login/invitation бюджеты разделены; квоты провайдеров общие. Это локальные defaults
  по команде реализации; остальные численные предложения D07 не принимаются автоматически.
- Миграция 012: PostgreSQL reservations/ledger, атомарность между API-процессами,
  HMAC email/IP ключи, сохранение при restart, 429 + Retry-After и countdown в Admin.
- Упорядоченные провайдеры; rolling 24h и фактический billing cycle с UTC anchor,
  reserved headroom. Переключение только до отправки при исчерпании локальной квоты.
- Pending/unknown никогда автоматически не дублируются. Даже definitive rejection
  требует нового явного запроса; `accepted` означает приём API, не доставку в ящик.
- Ручные/внешние отправки не синхронизируются с provider usage: dedicated account
  или настроенный резерв и сверка dashboard обязательны при подключении.
