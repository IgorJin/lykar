# SERVICE-V1-21 — Пилот на согласованных реальных сайтах

Status: PLANNED
Priority: P0
Depends on: SERVICE-V1-19, SERVICE-V1-20
Parallel wave: W19
Can run in parallel with: None

Stage: E7 — Пилот и решение об открытии сервиса
Planning date: 2026-10-02

## Goal

Подтвердить полезный результат сервиса за пределами fixtures.

## Problem solved

Техническая матрица не доказывает самостоятельное использование клиентом и совместимость конкретного внешнего сайта.

## Enables

- Проверенную готовность первой версии сервиса.
- Приоритизацию обнаруженных проблем по влиянию на клиента.

## Scope

- Провести утверждённый 20 протокол на разрешённых владельцем сайтах/участниках с принятым candidate.
- Зафиксировать самостоятельное выполнение каждого шага, помощь оператора, time-to-result, ошибки и повторную правку.
- Проверять A/B через специальные ссылки и контролируемые события при допустимом consent; не заявлять результат конверсии на искусственном трафике.
- Показывать unsupported случаи честно; не расширять Next.js/другие адаптеры под видом исправления.
- Собрать дефекты; потеря данных/доступ/неверный отчёт блокируют дальнейший запуск. Исправления возвращаются в соответствующие задачи с повтором impacted checks и candidate gate.

## Parallel execution

Последовательно после 19/20, один оператор координирует доступ и релиз; клиентские сайты не используются как общий тестовый стенд без разрешения.

Hard prerequisites: SERVICE-V1-19, SERVICE-V1-20. Все транзитивные prerequisites обязательны. Изменение общей схемы/контракта/lockfile или использование одного mutable стенда требует последовательного checkpoint.

## Acceptance criteria

- [ ] Утверждённые сценарии выполнены на утверждённой выборке либо результат явно FAIL/BLOCKED с причиной.
- [ ] Каждый критичный дефект имеет воспроизведение и проверенное исправление; закрытие не основано на устном обещании.
- [ ] Отчёт различает самостоятельное прохождение, помощь и неподдержанный сайт.
- [ ] Оценка полезности/повторного использования записана без выдуманных участников или метрик.

## Checks

- `AGREED` — `BROWSER`: Browser E2E: регистрация → подключение → правка → preview → публикация/эксперимент → отчёт → отключение; static, React/Vue в пределах принятой S4-матрицы. Полный проход Chromium, ключевые сценарии Firefox/WebKit.
- `AGREED` — `UI`: UI и ручная приёмка: desktop/mobile, клавиатура, фокус, ошибки, сохранность правок и диагностика подключения.
- `AGREED` — `RELIABILITY`: Надёжность, безопасность и performance: потеря/задержка сети, исходная страница при сбое, отсутствие дублей аналитики, изоляция доступа, consent, лимиты запросов, отсутствие токенов в логах; измерение доставки/replay и согласование новых численных бюджетов до реализации.

Точная привязка согласованных слоёв к этой задаче:
- `AGREED` — AGREED group-level пользовательский пилот после технической приёмки; конкретная выборка и protocol из 20.
- `AGREED` — При исправлениях — targeted regression и обновление release candidate evidence 19.

Необходимый environment и evidence — в [TEST-PLAN.md](./TEST-PLAN.md). Новые suites/commands сначала создаются в рамках scope; отсутствие команды не трактуется как успешная проверка.
