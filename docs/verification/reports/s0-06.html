Архитектура потока

Capability lifecycle

После exchange bearer capability хранится в sessionStorage одной вкладки. Код в URL удаляется. Истечение, другой path или повреждённый JSON очищают запись.

Backend как источник

Reload и новый popup получают операции через защищённый GET Draft. Локальный pending storage используется только для ещё не сохранённых команд.

Разделение контекстов

Owner, share visitor и native visitor имеют разные cookies/storage. Поэтому share не может пройти за счёт сессии владельца.
