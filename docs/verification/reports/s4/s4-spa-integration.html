Что реализовано

  1. Build plugins автоматически инструментируют createRoot/hydrateRoot/createApp/createSSRApp; публичные lifecycle APIs подтверждают readiness.
  2. Operation schema 2 хранит исходный текст и общую группу. Старые runtimes отвергают новую операцию. Manifest envelope остаётся schema 1.
  3. Observer разделяет host mutations и собственные записи; синхронно включает/снимает effects, поддерживает remount и bounded cleanup.
  4. Editor захватывает вариант при выборе, сохраняет history/recovery и tombstone undo. Изменившийся во время редактирования вариант требует повторного выбора.
  5. API сохраняет conditional operations в существующих JSON payloads. Release/share остаются immutable и page-scoped.
  6. SDK наблюдает pathname navigation, отменяет старые сессии и сохраняет share access только для соответствующей страницы в текущем экземпляре.
  7. Script SDK загружает runtime-core только при необходимости, с manifest compatibility и SRI. Npm ESM остаётся самодостаточным; lazy editor сохраняется.

Поддержка и границы

  • React 19.2.8 / React DOM 19.2.8 и Vue 3.5.18: CSR и обычная SSR/hydration. Esbuild 0.28.1 и production Vite 8.2.0.
  • Однократное подключение npm/build plugin; компоненты не добавляют hooks, markers или бизнес-state exports. Runtime не вызывает AI.
  • Условие — исходный plain text уникального элемента. «Продолжить» получает «Далее» и navy, «Ожидаем» сохраняет host rendering. Одинаковый исходный текст не различает скрытые условия.
  • Текстовый узел сохраняется при записи Lykar. Vue может сам заменять его при смене текста. Стили накладываются отдельным CSS-правилом, без изменения host inline.
  • Неоднозначность, потеря готовности, mutation flood, CSP/inline-important конфликт приводят к пропуску или остановке с диагностикой. Для literal color/background-color дополнительно проверяется фактический CSS cascade.
  • Next.js, streaming/RSC/selective hydration, portals/Shadow DOM, Vite dev/HMR и structural edits framework tree не входят в этот S4.
  • CSSOM-изменения существующего правила обнаруживаются при следующем sync/наблюдаемом DOM-событии. Автоматический вывод произвольных условий в исходном коде не заявляется.
  • Prepaint проверен после готовности rules/root. При поздней загрузке исходный первый кадр может быть виден. Скриншоты и проверка desktop/mobile не являются полным visual/a11y аудитом.

Воспроизведение

Выполнять команды последовательно: workspace dist и временный тестовый стенд общие. Browser/API checks требуют локальной PostgreSQL и установленных Chromium/Firefox/WebKit. Packed framework consumer устанавливает зависимости в отдельную временную директорию.

Machine evidence: checks.json, snapshot.json, performance.json и assets/*-evidence.json. Prepaint evidence содержит кадры только после загрузки правил и готовности root.
